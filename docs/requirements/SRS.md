# 软件需求规格说明书

## 1. 文档信息

- 项目：智能知识库管理系统
- 阶段：S01 需求分析与项目立项
- 版本：0.1（需求基线候选）
- 日期：2026-10-08（Asia/Shanghai）

## 2. 产品范围与使用者

系统面向单机使用者：使用者在自己的计算机上导入学习资料，建立本地知识库，进行检索问答、学习规划和练习。第一版不提供注册、登录、角色、权限、租户、共享库、用户管理或遥测功能。业务数据和运行数据默认留在本机；系统默认仅监听本机。

### 2.1 核心闭环

1. 创建知识库并导入 PDF、DOCX、TXT、Markdown。
2. 查看解析、分段和嵌入状态，预览文本并管理资料。
3. 在指定知识库内检索问答，查看可打开的来源。
4. 依据目标和时间生成学习计划，执行并调整计划。
5. 从资料生成题目，作答后获得判分、解析和学习记录。

## 3. 约束与边界

### 3.1 必做范围

- 文本型 PDF、DOCX、TXT、Markdown 的导入和本地管理。
- 知识库、文档、解析任务、问答会话、学习计划、练习记录的本地持久化。
- OpenAI 兼容公共 API 与 Ollama 两种模型服务配置路径；生成和嵌入配置分离。
- 严格资料模式与补充通用知识模式，来源与补充内容明确区分。

### 3.2 明确不做

旧版 DOC、扫描件 OCR、知识图谱、在线协作、云端托管、账号体系、多用户后台、公网无认证部署不属于第一版必做范围。课程展示、发布、云端推送和 Release 由 S09 处理，本阶段不实现。

## 4. 角色与用例

唯一角色为“单机使用者”。

| 用例 | 前置条件 | 主流程 | 异常/边界结果 |
|---|---|---|---|
| UC-01 管理知识库 | 应用已启动 | 创建、编辑名称/描述、查看、删除；删除前确认影响 | 空名称、重复名称、取消删除；删除有文档时必须展示影响并二次确认 |
| UC-02 导入资料 | 已选择知识库 | 选择文件，校验格式/大小，保存原文件，异步解析、分段、嵌入 | 不支持格式、超限、空/损坏文件、磁盘不足；失败可见且可重试 |
| UC-03 管理资料 | 已存在资料 | 列表、筛选、预览提取文本、下载、删除 | 解析中不可误显示为可检索；删除后原文件和索引片段均应清理 |
| UC-04 检索问答 | 知识库有可用片段 | 选择范围和回答模式，提问，多轮追问，查看来源 | 无命中/资料不足明确拒答；不得跨库；模型超时、限流或输出错误可理解 |
| UC-05 配置模型 | 使用者有服务地址/模型信息 | 配置并测试生成与嵌入服务 | 缺少密钥、地址错误、维度不匹配、超时；密钥不回显、不写日志 |
| UC-06 制定学习计划 | 输入目标、基础、截止日期、每日时间 | 生成、编辑、排序、完成任务，按进度重新规划 | 日期不合法、时间不足、资料不足、模型格式错误；失败不破坏已有计划 |
| UC-07 练习与反馈 | 有可用资料或计划范围 | 设范围/题型/难度/题数，生成题目，作答并提交 | 题目格式或来源不足；提交前不得返回答案；重复提交和非法答案有明确处理 |

## 5. 可验证需求

每项需求至少具有正常和异常验收条件；详细映射见 `TRACEABILITY.md`。

### R01 知识库管理（P0）

- 正常：使用者可创建、查看、编辑名称和描述、删除知识库。
- 异常：名称为空/重复时拒绝并提示；删除前显示文档、索引和会话影响并要求确认；取消后数据不变。

### R02 文档管理（P0）

- 正常：支持 PDF、DOCX、TXT、Markdown 的上传、列表、筛选、文本预览、下载和删除。
- 异常：格式和大小校验在保存前生效；损坏、空文本、不可读文件有明确错误；文件路径不能逃逸数据目录。

### R03 文档处理（P0）

- 正常：上传后可观察解析、分段、嵌入状态，成功后可检索；失败可重试；重启可恢复未完成任务。
- 异常：处理失败不伪装成功，重试不产生重复片段；任务异常原因可见。

### R04 一致性（P0）

- 正常：删除资料后原文件、处理结果和已有索引均不再提供检索命中。
- 异常：删除/重试/进程中断期间不得留下可见孤儿索引；恢复后状态与实际存储一致。

### R05 检索问答（P0）

- 正常：问答严格限制在选定知识库，多轮会话保留上下文，来源可打开到文档位置。
- 异常：资料不足给出明确反馈；任何情况下不得泄漏其他知识库内容。

### R06 回答模式（P0）

- 正常：严格资料模式只依据检索资料；补充模式将通用补充和资料结论分开标识。
- 异常：模型无法区分来源或资料为空时，不得把通用内容伪装成资料结论。

### R07 学习计划（P1）

- 正常：输入目标、基础、截止日期、每日时间后生成可编辑、可排序、可完成的计划，并保存进度。
- 异常：日期/时间非法或资料不足时拒绝或明确提示；生成失败不覆盖已有计划。

### R08 计划调整（P1）

- 正常：根据进度重新规划未完成任务，保留已完成任务和已有学习记录。
- 异常：调整失败保留原计划；不可行时间安排给出原因而非生成虚假可行结果。

### R09 智能出题（P1）

- 正常：按范围、数量、难度生成单选、判断、简答题，附答案、解析和来源。
- 异常：校验选项数量、答案范围、单选唯一性和来源；有限修复失败后明确报错。

### R10 作答反馈（P1）

- 正常：作答前接口不返回答案/解析；提交后客观题准确判分，简答题提供标注为辅助评价的反馈，并保存记录。
- 异常：非法答案、重复提交、评分服务不可用可理解处理；已提交记录不丢失。

### R11 模型配置（P0）

- 正常：可分别配置和测试公共 API 与 Ollama 的生成、嵌入服务，错误分类清晰，支持超时控制。
- 异常：密钥不入仓库/日志；嵌入维度或模型不兼容时阻止使用；本地模型失败不得隐式回退公共 API。

### R12 本地交付（P0）

- 正常：无需账号即可使用；数据本地持久化；按 README 在干净环境完成启动。
- 异常：默认不监听公网；本地目录不可写、配置缺失或依赖不满足时有可操作提示。

## 6. 跨功能质量要求

- 安全：防路径穿越、非法上传、密钥泄露和文档提示注入；模型输出视为不可信输入。
- 可观察性：耗时任务显示状态、进度或阶段及失败原因；不承诺固定模型响应时长。
- 可维护性：REST JSON 契约先于业务实现，数据结构和状态应可测试。
- 可用性：桌面和窄屏不出现明显遮挡或溢出；关键操作有确认和错误恢复。

## 7. 规模、性能与运行假设

S01 只建立测量口径，不承诺未经验证的数字。基线样本建议为单机 1 名使用者、1--20 个知识库、每库 1--500 份资料、单文件不超过 50 MB、总本地资料不超过 5 GB、单文档不超过 200 页或 2,000,000 字符。实际可支持上限由 S02 原型和 S08 测量修订。

- 解析耗时：从上传确认到文本可预览，记录文件大小、页数/字符数和本地处理耗时。
- 索引耗时：从解析完成到可检索，记录分段数、嵌入批次、模型类型和外部调用耗时。
- 检索耗时：记录服务端检索耗时与端到端首结果耗时，区分本地索引和模型生成。
- 生成耗时：记录首 token 和完整回答耗时；外部模型不可用时记录失败类型，不伪造性能结论。
- 资源：记录测试机 CPU、内存、磁盘、操作系统、Java/Node 版本及模型配置。

## 8. 外部依赖与前置条件

应用依赖 Java 21、Node.js/npm、浏览器和可写本地数据目录；公共 API 依赖使用者提供的兼容服务地址/密钥/模型，Ollama 依赖本机服务与已拉取模型。S02 负责固定具体依赖版本和验证组合。缺少模型服务时，确定性测试仍应可运行，但不能将模拟结果当作真实接入验收。

## 9. 核心流程案例

### CASE-01 从资料到问答

使用者创建“Java 基础”知识库，上传一份文本型 PDF。系统校验后显示“处理中”，成功后显示可预览文本和可检索状态。使用者在该库提问，回答展示引用文档和定位。若提问内容超出资料，严格模式返回资料不足；删除 PDF 后相同问题不再命中它。

### CASE-02 计划与练习

使用者输入“在 14 天内掌握集合框架”、已有基础和每日 45 分钟，系统生成带资料引用的任务。使用者完成部分任务后调整计划，已完成任务和学习记录保留。随后按已学范围生成单选、判断、简答题；提交前看不到答案，提交后获得客观判分和标注为辅助评价的简答反馈。
