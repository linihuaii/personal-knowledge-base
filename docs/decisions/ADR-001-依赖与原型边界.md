# ADR-001：依赖与原型边界

- 状态：S02 候选决策，待审核
- 日期：2026-10-08（Asia/Shanghai）

## 背景

项目需要本地单机部署、成熟解析能力、可恢复向量索引和两类模型服务，但正式依赖必须在最小原型和兼容性验证后固定。

## 决策

1. 后端以本机 JDK `17`（当前 `javac 17`，运行时 build `17+35`）为基线，Spring Boot 固定 `3.5.6`、Maven Wrapper 固定 `3.9.11`；文档解析候选 Apache Tika `3.2.2`、PDFBox `3.0.5`，数据库候选 H2 `2.3.232`。具体组合须在 S02 原型中验证，不能仅凭版本清单认定兼容。
2. 文档解析优先评估 Apache Tika 与 PDFBox 组合；解析器只负责产生带定位元数据的纯文本，不让解析器内容成为系统指令。
3. 第一版采用自研的本地暴力余弦索引：单个 `index-v1.json` 原子快照，包含 manifest、片段映射和定长向量，按知识库过滤后计算余弦相似度。保存时先写同目录临时文件，再一次替换快照；进程中断只会保留旧快照或完整新快照，不存在 manifest/向量撕裂。它不需要额外向量数据库，适合 S02 目标的单机规模；代价是 O(n) 查询、无 ANN、并发写入和大规模数据性能有限，S08 必须测量并在超限时考虑替换为固定版本的库。
4. 模型适配器拆分生成与嵌入接口；公共 API 仅承诺经过验证的 OpenAI 兼容协议，Ollama 单独配置，不允许隐式回退。

## 证据与未决项

`experiments/retrieval_prototype.py` 可离线验证：自制 TXT、Markdown、结构有效的 DOCX ZIP/XML、带交叉引用表的最小 PDF 样本解析、按字符窗口分段、确定性向量、单文件原子快照、库过滤、重载、删除后不命中和维度不匹配拒绝加载。脚本实际发送 OpenAI 兼容 `/v1/embeddings` 与 Ollama `/api/embed` 请求，并探测模型列表端点；当前均连接失败。以上是原型解析器和索引生命周期证据，不是 Tika/PDFBox 或真实模型通过证据。

## 版本与兼容性核对

| 组件 | 固定版本 | 当前环境证据 |
|---|---|---|
| JDK | 17（本机 build `17+35`） | `java -version`、`javac -version` 已确认；尚未运行项目构建 |
| Spring Boot | 3.5.6 | 官方 3.5 系列最低要求 Java 17；Maven Wrapper 尚未创建，未构建 |
| Maven Wrapper | 3.9.11 | 尚未创建工程，未执行 |
| Apache Tika | 3.2.2 | 未下载，未执行 |
| PDFBox | 3.0.5 | 未下载，未执行 |
| H2 | 2.3.232 | 未下载，未执行 |

| 本地向量索引 | 自研单文件原子快照 `index-v1.json`，manifest/片段/向量同一快照 | 标准库原型已验证重启、库过滤、删除、维度负例；未验证目标规模性能 |

本机已有 JDK 17；Maven 未安装，需通过 Maven Wrapper 执行依赖解析。当前环境仍不能证明完整依赖组合兼容，S02 审核缺项未因本次基线调整自动消除。

Spring Boot 3.5 的 Java/Maven 要求参见[官方系统要求](https://docs.spring.io/spring-boot/3.5/system-requirements.html)；该文档只证明版本基线允许 JDK 17，不代替本项目依赖组合的运行验证。

## 兼容性替代方案

若目标规模测量显示 O(n) 索引不足，需在 JDK 17 下重新选择并验证替代组件；原 Lucene `10.3.1` 候选不再作为已确定方案。切换前须验证过滤、删除、重启和索引版本迁移。

## 替代方案

远程向量数据库、云端文档解析和把公共 API 作为本地模型兜底均不采用：它们扩大部署依赖、数据外传或违背本地模型不隐式回退约束。
