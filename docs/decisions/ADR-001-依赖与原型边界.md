# ADR-001：依赖与原型边界

- 状态：S02 候选决策，待审核
- 日期：2026-10-08（Asia/Shanghai）

## 背景

项目需要本地单机部署、成熟解析能力、可恢复向量索引和两类模型服务，但正式依赖必须在最小原型和兼容性验证后固定。

## 决策

1. 后端继续采用 Java 21 + Spring Boot 3.x + Maven；具体 Spring Boot、Tika/PDFBox、H2 和向量组件版本在 S02 环境验证后锁定，未验证前不写入浮动依赖。
2. 文档解析优先评估 Apache Tika 与 PDFBox 组合；解析器只负责产生带定位元数据的纯文本，不让解析器内容成为系统指令。
3. 第一版向量索引必须随应用本地持久化，不依赖额外向量数据库。原型使用确定性哈希向量验证生命周期和过滤语义，不能替代真实嵌入质量验证。
4. 模型适配器拆分生成与嵌入接口；公共 API 仅承诺经过验证的 OpenAI 兼容协议，Ollama 单独配置，不允许隐式回退。

## 证据与未决项

`experiments/retrieval_prototype.py` 可离线验证：分段、确定性向量、库过滤、保存/重载、删除后不命中。当前没有可安全提交的真实资料、模型密钥或保证可用的外部服务，因此 PDF/DOCX 实际解析、真实嵌入质量、公共 API 和 Ollama 连通性暂记为未验证项；其缺失影响 S04/S05 的真实验收，不阻止 S02 设计完成，但需在对应阶段明确记录。

## 替代方案

远程向量数据库、云端文档解析和把公共 API 作为本地模型兜底均不采用：它们扩大部署依赖、数据外传或违背本地模型不隐式回退约束。
