# ADR-001：依赖与原型边界

- 状态：S02 候选决策，待审核
- 日期：2026-10-08（Asia/Shanghai）

## 背景

项目需要本地单机部署、成熟解析能力、可恢复向量索引和两类模型服务，但正式依赖必须在最小原型和兼容性验证后固定。

## 决策

1. 后端固定为 Java `21.0.8`、Spring Boot `3.5.6`、Maven Wrapper `3.9.11`；文档解析固定 Apache Tika `3.2.2`、PDFBox `3.0.5`，数据库固定 H2 `2.3.232`。这些版本作为 S03 的锁定输入。
2. 文档解析优先评估 Apache Tika 与 PDFBox 组合；解析器只负责产生带定位元数据的纯文本，不让解析器内容成为系统指令。
3. 第一版采用自研的本地暴力余弦索引：manifest JSON + 定长向量文件，按知识库过滤后计算余弦相似度。它不需要额外向量数据库，适合 S02 目标的单机规模；代价是 O(n) 查询、无 ANN、并发写入和大规模数据性能有限，S08 必须测量并在超限时考虑替换为固定版本的库。S02 原型验证其重启、过滤、删除和维度校验生命周期；真实嵌入接入需按模型契约单独验证。
4. 模型适配器拆分生成与嵌入接口；公共 API 仅承诺经过验证的 OpenAI 兼容协议，Ollama 单独配置，不允许隐式回退。

## 证据与未决项

`experiments/retrieval_prototype.py` 可离线验证：自制 TXT、Markdown、结构有效的 DOCX ZIP/XML、带交叉引用表的最小 PDF 样本解析、按字符窗口分段、确定性向量、库过滤、manifest/向量文件分离保存与重载、删除后不命中和维度不匹配拒绝加载。脚本实际发送 OpenAI 兼容 `/v1/embeddings` 与 Ollama `/api/embed` 请求，并探测模型列表端点；当前均连接失败。以上是原型解析器和索引布局证据，不是 Tika/PDFBox 或真实模型通过证据。

## 版本与兼容性核对

| 组件 | 固定版本 | 当前环境证据 |
|---|---|---|
| Java | 21.0.8 | 当前 `java -version` 为 17，未通过，环境缺失 |
| Spring Boot | 3.5.6 | Java 17+ 基线与目标 Java 21 不矛盾；Maven 未安装，未构建 |
| Maven Wrapper | 3.9.11 | 尚未创建工程，未执行 |
| Apache Tika | 3.2.2 | 未下载，未执行 |
| PDFBox | 3.0.5 | 未下载，未执行 |
| H2 | 2.3.232 | 未下载，未执行 |

| 本地向量索引 | 自研 JSON manifest + 定长向量文件，版本 `index-v1` | 标准库原型已验证重启、库过滤、删除、维度负例；未验证目标规模性能 |

版本已固定，但当前环境不能证明完整兼容性；S03 必须先提供 Java 21 和 Maven Wrapper，再执行依赖解析、启动和迁移验证。

## 兼容性替代方案

若 S03 的目标规模测量显示 O(n) 索引不足，候选替代为 Lucene `10.3.1`（Java 21 目标运行时），但本阶段不引入或宣称已验证；切换前需重新验证过滤、删除、重启和索引版本迁移。

## 替代方案

远程向量数据库、云端文档解析和把公共 API 作为本地模型兜底均不采用：它们扩大部署依赖、数据外传或违背本地模型不隐式回退约束。
