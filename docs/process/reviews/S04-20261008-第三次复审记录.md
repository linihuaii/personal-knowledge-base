## 审核证据

- 核对 `70a172f..7378b5d`：本轮业务代码仅将 `vector()` 的数组长度由 8 改为 768；页面、任务恢复、索引调用点和测试均未改动。审核前工作树无未提交变更。
- `vector()` 仍按词哈希计数生成数组，没有调用 Ollama 或其他真实嵌入服务；`persistIndex()` 仍无调用点，且写入的元数据维度仍固定为 8。
- V4 将 `vector_json` 定义为 `varchar(2000)`。即使 768 个值全为 `0.0`，按 Java `Arrays.toString(double[])` 的格式也需 3,840 个字符，超过字段上限；因此片段插入会失败，文档不能可靠进入 `READY`。
- 本轮日志明确承认四格式集成矩阵、页面全流程和索引调用点仍未完成；未提交新的 S04 业务测试。前次的 3 项后端基础测试不能证明这些验收项。

## 问题与处理要求（按严重程度）

1. **高：向量字段容量直接阻断文档处理。** `vector_json varchar(2000)` 无法保存当前 768 维 `Arrays.toString` 结果；按新增迁移扩大为适合的类型，并用四格式上传和片段入库验证，而非仅运行空库迁移。
2. **高：索引和嵌入仍未接通。** 维度改为 768 不等于 S02 已验证的 `nomic-embed-text-v2-moe` 嵌入；索引生成器未被调用且宣称维度 8，上传、重试、删除均不会同步索引。按已批准方案接入模型、索引生命周期与指纹校验，或先申请相关设计变更；验证删除后无命中。
3. **高：删除失败恢复未闭环。** `FAILED_RETRYABLE` 中的 `DELETE_FAILED` 仍会被 `/retry` 当作解析失败重新处理；启动恢复仍不处理 `DELETING`。修复状态机并做失败注入与重启验证。
4. **中：R01/R02 页面仍不完整。** `editBase()`、`deleteBase()` 只存在于客户端，页面无知识库编辑/删除；资料筛选和原文件下载入口仍缺。补全页面并验证确认、取消及错误反馈。
5. **中：阶段提交与验收记录未完成。** 四格式成功、损坏/空文本、重试去重、并发删除、重启恢复等 S04 证据仍缺；阶段索引还写“本次返工提交待生成”，应回填 `7378b5d` 或后续最终待审核版本。
