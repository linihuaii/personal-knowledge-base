## 问题（按严重程度）

1. **P1：学习计划来源外键阻断既有文档删除与索引重建。** `V8__study_plans.sql` 的 `study_task_source.chunk_id` 直接引用 `document_chunk(id)`，而 `LibraryService` 的删除、重试处理及重建索引都先删除旧片段。只要有计划引用该片段，删除语句就受外键约束失败；文档删除甚至可能已先删除原文件，再进入 `DELETE_FAILED`。需要明确来源历史与文档删除策略，使删除和重建均可成功，并保持计划可读、引用状态诚实。
2. **P1：前端无法正确使用后端计划响应。** `StudyPlanService.plan()` 用 `JdbcTemplate.queryForList` 的数据库列名直接组成 Map，计划与任务字段为 `ID`、`GOAL`、`SCHEDULED_DATE` 等；`StudyView.vue` 与 `client.ts` 却按 `id`、`goal`、`scheduledDate` 等读取。生成后 `refresh()` 不会按计划 ID 读取，选择计划时表单字段为 `undefined`，任务渲染、完成标记和保存也使用错误字段。需要在 API 统一输出稳定的 camelCase 契约，或在客户端完整归一化，并用真实响应验证全流程。
3. **P2：经过计划日期后编辑会被无关的历史任务阻断。** `normalizeInputs()` 对每个任务调用要求日期晚于今天的 `validDate()`，包括已经完成的历史任务。计划跨日后，保存其他任务时也会因已完成任务原日期在过去而返回 `PLAN_INVALID`。应允许保留已完成记录的历史日期，只校验可编辑任务的安排。
4. **P2：S06 关键验收缺少可运行证据。** 当前验证记录明确写明 `StudyPlanTests` 未执行完成、HTTP 冒烟未完成、真实生成未运行。修复后需补充计划生成、编辑排序、完成、重新规划、格式错误/资料不足、来源跳转、文档删除及索引重建的实际验证结果；真实模型行为应与模拟测试分别记录。
