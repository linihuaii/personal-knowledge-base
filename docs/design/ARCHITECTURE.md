# 总体架构设计

阶段：S02；版本：0.1；日期：2026-10-08（Asia/Shanghai）。

## 1. 部署结构

系统采用本机单用户部署：Vue 3 前端由 Vite 构建，Spring Boot 3.x 后端提供 REST JSON 和问答 SSE；后端使用 H2 文件数据库保存业务元数据，文件系统保存原始资料与处理结果，向量索引保存于数据目录。应用默认绑定 `127.0.0.1`，不假设认证或公网访问。

```text
浏览器
  │ HTTP/JSON、SSE
  ▼
Vue 3 + Router + Pinia
  │ REST API
  ▼
Spring Boot API
  ├─ 知识库/文档/会话/计划/练习服务
  ├─ 文档处理任务协调器 ── 数据目录/raw + processed
  ├─ H2 文件数据库（业务状态）
  ├─ 向量索引（本地持久化）
  └─ 模型适配器 ── OpenAI 兼容 API / Ollama
```

## 2. 模块边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| Web UI | 页面状态、表单、来源跳转、SSE 展示 | 安全判定、答案隐藏、最终评分 |
| REST API | 校验、授权边界（单机范围）、统一错误、事务入口 | 直接信任前端字段 |
| 文档服务 | 文件安全存储、格式校验、预览与下载 | 模型生成 |
| 处理任务 | 解析、分段、嵌入、可恢复状态、幂等 | 用户界面渲染 |
| 检索服务 | 知识库过滤、相似度排序、引用映射 | 跨库聚合 |
| 模型适配器 | 生成/嵌入接口、超时、错误分类、配置测试 | 业务提示词规则 |
| 计划/练习服务 | 结构校验、持久化、确定性判分 | 绕过来源约束生成答案 |
| 数据层 | H2、文件系统、索引原子写入 | 远程数据库 |

## 3. 数据流

### 3.1 导入到检索

上传请求 → 扩展名/MIME/大小校验 → 生成内部 ID 和安全文件名 → 原文件落盘 → 文档状态 `UPLOADED` → 后台任务取得租约 → 解析并保存文本 → 分段并保存片段元数据 → 以配置指纹调用嵌入 → 临时索引写入并校验 → 原子替换索引 → 文档 `READY`。任何失败都保存错误类型和可重试状态。

### 3.2 问答

问题 + 会话 + 知识库 ID → 过滤 `READY` 文档 → 向量检索 top-k → 生成引用上下文（带片段 ID、文档 ID、位置）→ 根据模式生成提示 → SSE 发送 token/引用/完成或失败事件 → 持久化会话消息和来源。严格模式的提示明确只允许上下文；补充模式将“资料结论”和“通用补充”分块。

## 4. 状态与恢复原则

- 文档处理状态：`UPLOADED → PROCESSING → READY`，异常为 `FAILED_RETRYABLE` 或 `FAILED_FINAL`。
- 任务含唯一 `document_id + pipeline_version + embedding_fingerprint` 幂等键；重试前清理该键的临时产物。
- 启动时扫描 `PROCESSING` 和过期租约任务，恢复为可重试；不直接标记成功。
- 索引更新写入临时文件并 fsync/校验后替换清单；清单只引用已存在的片段。
- 删除顺序：标记文档删除/禁止检索 → 事务删除片段和任务 → 从索引生成新快照并替换 → 删除处理文件和原文件 → 写审计级操作日志。任一步失败保留可恢复状态，不宣称完成。

## 5. 安全与边界

所有文件路径由数据根目录解析并校验 real path 在根目录内；模型输出和导入文档内容均视为不可信；文档中的指令不能改变系统规则。公共 API 请求前明确提示可能发送所选片段；密钥只来自本地配置/环境变量，日志只记录脱敏服务标识。

## 6. S02 原型结论

`experiments/retrieval_prototype.py` 验证了无第三方向量数据库的哈希向量、知识库过滤、索引 JSON 持久化、重启加载和删除后不命中。真实 PDF/DOCX 解析、真实嵌入模型、OpenAI 兼容服务和 Ollama 在当前环境未作为通过项；依赖与影响记录见 `docs/decisions/ADR-001-依赖与原型边界.md`。
