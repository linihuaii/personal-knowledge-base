# S07 题目质量抽查记录

日期：2026-10-09（Asia/Shanghai）

## 抽查范围

检查单选、判断、简答三种结构化题目的来源、标准答案和解释，并核对提交前答案隔离与客观题判分。先使用确定性 JSON 样本跑结构与规则测试，再使用本机 Ollama `gemma4:e4b` 对下方合成资料进行一次实时出题和简答评分抽查。

抽查使用自制测试资料摘录：“List 保持顺序并允许重复元素。Set 不允许重复元素。Map 使用键值对保存数据。”所有题目引用具体 `chunkId`；API 对引用执行当前知识库、READY 文档和活动索引校验。

## 样题核对

| 题型 | 题干 | 标准答案 | 来源事实 | 核对结果 |
|---|---|---|---|---|
| 单选 | 若要保存一组不能重复的元素，应选择哪种集合？选项：List / Set / Map / Array | B | 摘录称 Set 不允许重复元素 | 实际输出答案 B；四项去掉模型自带的字母前缀后各不相同，只有 Set 符合 |
| 判断 | Map 使用键值对方式保存数据 | TRUE | 摘录称 Map 使用键值对保存数据 | 实际输出 TRUE；服务端按 TRUE/FALSE 确定性判分 |
| 简答 | 哪种 Java 集合具有保持顺序并允许重复元素的特点？ | List | 摘录称 List 保持顺序并允许重复元素 | 实际参考答案为 List；实际评分器对“按加入顺序保存、可以有相同元素”给 1.0，并说明两点均答出 |

实时调用均使用自制摘录和合成 `chunk-demo-001`，未发送项目使用者资料。模型响应为严格 JSON，输出 3 题，覆盖请求的三种类型，均引用允许的 chunk ID；单选选项前缀被后端归一化，避免 UI 重复显示字母。

## 校验结论与限制

- 服务端强制题数、允许题型、单选 4 个不同选项、答案标签范围、判断答案范围、来源 ID 归属及题干/答案/解释长度；结构错误会触发一次修复，仍无效则不创建练习记录。
- 实际模型抽查仅为一组短样本，不能代表所有资料、难度和运行环境；S08 仍需使用固定评估资料扩大真实模型质量检查。
- 单选语义唯一性不能仅靠 JSON schema 证明；本阶段对上述样题人工核对，S08 继续对真实样本抽查。
